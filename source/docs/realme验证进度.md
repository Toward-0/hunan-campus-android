# 当前交付结论：0.2.2

日期：2026-10-31。本版已安装到目标 realme RMX3820，采用 iOS 动态兼容通道实现独立认证上网；原生 Android C075 通道仍未适配。这里的通过结论仅覆盖本机与本次校园网，不代表八小时后台或所有 ROM 已验收。

## 本轮通过
- 普通首页操作：登录 → HTTPS外网200 → 服务端确认注销 → HTTP恢复302门户拦截 → 再次登录成功。
- 覆盖安装保留账号密码和原配置；当前临时测试门户已经清空。
- 手动停止后 Wi-Fi 变化和重新打开页面不自动登录；在线停止后再启动可使用同IP/网关、外网重新验证过的身份缓存恢复。
- 10次完整 Wi-Fi 断开重连，均为 ChinaNet-Young、客户端认证成功和外网HTTP200。额外两次界面不在前台未取得状态，未计入通过，已经补测。

- 临时Wi-Fi代理恢复“无”，ADB reverse映射为空；延迟端点已自行退出。
- 真机JNI：3份已有样本逐字节解密/重加密一致，旧核心4000次并发调用；动态上下文100次创建/释放、UTF-8和块边界、失效句柄、容量回收、4000次并发往返、并发释放后重启均通过。不是Android服务100次启停的结论。
- 0.2.1完成主要网络重连验收；0.2.2仅扩大并限制日志容量，已重新完成构建、覆盖升级、请求中停止和正常界面登录复核。
- 构建、Lint（0错误/10警告）、v2/v3签名通过；测试签名，尚非正式发布密钥。

## 关键定位
官方成功取样下发的 ticket/auth/state 接口仍为175.12.104.1:10001，官方 Android 请求采用 CCTP/android64_vpn/2029、C075B749-22F3-4D9F-A4A6-8BFF04C03817，与原POC Windows通道不同。仅把UA改成Android会触发协议码200的动态模块下发，不能继续用固定湖南算法硬解。

现有r8 C源码中可用的 iOS 动态 ZSM 解包与移动算法被单独接入JNI，在本机完成真实放行。没有执行服务端模块中的JS或本机代码。尚未定位旧Windows通道接口全0而数据面未放行的唯一服务端原因；已通过兼容通道满足当前APK独立上网的功能关口。

## 架构说明
延续旧 APK：Kotlin 负责 HTTP、调度和凭据，JNI 仅复用 C 加密及 XML。这是验证候选，不是完整 C 会话核心库化完成版；桌面回归结论不适用于 Android。尚未满足用户给出的完整产品验收要求。

HTTP 协议没有 TLS 保护；保留应用层加密。凭据由 Keystore 加密保存，备份关闭。诊断结果仍可能包含设备/网络状态，分享前检查。
