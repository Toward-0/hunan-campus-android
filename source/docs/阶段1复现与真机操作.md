# 阶段1复现与真机操作

本阶段版本为 0.2.19-compat-s1 / 31，minSdk 26、targetSdk 35。candidate-phone 是主包 org.esurfing.hunan；带 isolation 的三个 APK 都是 org.esurfing.hunan.isolation。arm32 仅用于实际 32 位进程验证，x86_64 仅用于模拟器，不能作为手机交付包。

## 隔离、预算和停止条件

以下自动测试不执行任何生产认证。真实登录上限 **0**、真实注销上限 **0**、外网探测上限 **0**。测试服务器在 Android 设备自身的 127.0.0.1 上；不使用 adb reverse，不将手机回环当作电脑回环。合成账号、模块和票据只存在隔离包。修复用例的 100 秒是客户端等待策略。

JNI 每次最多 180 秒；UI 每组最多 100 秒；传输每次最多 180 秒；六条修复路径每次最多 480 秒。完整生命周期压力用例包含两组各 100 次回环会话，预算 600 秒；初次 180 秒超时记录保留，不能据此宣称通过。网络请求均为隔离回环请求或不产生网络 I/O 的假连接。JNI 包含 200 次创建释放、182 组无效输入、9 种算法及每算法 20 个分配位置尝试。

设备离线/未授权、ABI 不匹配、安装或命令非零退出、测试超时、APK 哈希不符、出现非隔离前台窗口时停止该项，不自动重试认证。失败后保存该项记录并停止隔离包；不得以清除主应用数据解决失败。真实网络验证属于后续另行确认的方案。

## 新目录与构建

已封存目录只能读取。新一轮工作需创建新的 work/compat-s1-修订唯一标识 和 outputs/compat-s1-修订唯一标识。将 source.zip 解压为新阶段的 source/，将 scripts.zip 中的脚本放入新阶段根目录。工具链文件可读取复用；可写缓存、SDK、Android 用户目录、临时文件、AVD 和日志必须在新阶段下。

当前构建使用：JDK 17.0.16、Gradle 8.11.1、AGP 8.9.2、Kotlin 2.1.20、NDK 28.0.13004108、CMake 3.22.1、Build Tools 35.0.0。没有升级网络库。stage-env.ps1 中 JDK 与 build-stage.ps1 中 Gradle/测试签名路径是只读工具链引用；迁移机器时只修改新副本中的路径。

将已有 SDK 与 Gradle 用户缓存复制为新阶段 sdk/ 和 gradle-user/，不能用可写链接指向封存缓存。首次配置所需下载也进入新阶段。执行 PowerShell 7：

```powershell
$stage = 'D:/codex/新的工作目录/work/compat-s1-唯一标识'
$output = 'D:/codex/新的工作目录/outputs/compat-s1-唯一标识'
& "$stage/source/build-stage.ps1" -OutputRoot $output -BuildAbi phone
if ($LASTEXITCODE) { throw 'phone build failed' }
& "$stage/source/build-stage.ps1" -OutputRoot $output -BuildAbi arm32 -IsolationOnly -SkipLint
if ($LASTEXITCODE) { throw 'arm32 build failed' }
& "$stage/source/build-stage.ps1" -OutputRoot $output -BuildAbi x86_64 -IsolationOnly -SkipLint
if ($LASTEXITCODE) { throw 'x86_64 build failed' }
```

脚本会显式设置全部可写路径，使用 --offline --no-daemon，不在旧基线执行 Gradle；签名仅读取既有测试密钥，不生成正式密钥。每次构建的命令、时间、退出码、签名和最终 zipalign 检查写入新阶段 evidence/。不要直接双击 gradlew 绕过环境设置。

## Windows PowerShell / adb 操作

下例必须替换为实际路径，设备序列号、包名、APK 均显式指定。先 Environment，再根据 supported ABIs 选择 phone 或 arm32；缺少 armeabi-v7a 时禁止把 arm32 安装失败解释为 JNI 通过。

```powershell
$stage = 'D:/codex/新的工作目录/work/compat-s1-唯一标识'
$apk = 'D:/codex/新的工作目录/outputs/compat-s1-唯一标识/ESurfingHunan-0.2.19-compat-s1-isolation-phone.apk'
$common = @{
  Adb = "$stage/sdk/platform-tools/adb.exe"
  Aapt = "$stage/sdk/build-tools/35.0.0/aapt.exe"
  Serial = 'REPLACE_WITH_DEVICE_SERIAL'
  Package = 'org.esurfing.hunan.isolation'
  Apk = $apk
  EvidenceDirectory = "$stage/evidence/manual-realme-唯一标识"
}
& "$stage/source/tests/device/Verify-Compatibility.ps1" @common -Action Environment
if ($LASTEXITCODE) { throw 'Environment failed' }
& "$stage/source/tests/device/Verify-Compatibility.ps1" @common -Action Install -TimeoutSeconds 120
if ($LASTEXITCODE) { throw 'Install failed' }
& "$stage/source/tests/device/Verify-Compatibility.ps1" @common -Action JNI -TimeoutSeconds 180
if ($LASTEXITCODE) { throw 'JNI failed' }
& "$stage/source/tests/device/Verify-Compatibility.ps1" @common -Action Internet -TimeoutSeconds 180
if ($LASTEXITCODE) { throw 'Internet failed' }
& "$stage/source/tests/device/Verify-Compatibility.ps1" @common -Action Repair -TimeoutSeconds 480
if ($LASTEXITCODE) { throw 'Repair failed' }
& "$stage/source/tests/device/Restore-Compatibility.ps1" @common
```

每条命令失败立即停止，不盲目继续下一行。安装可能需要在 realme 上确认系统安装页面。本脚本拒绝非隔离 APK，核对安装后 SHA256，不卸载或清除主包。UI 动作只切页、滚动和输入框聚焦，不点击连接、注销、清除凭据按钮。字体和导航模式若人工调整，记录原值并在结束后恢复。

本次工具执行环境的原生 adb 客户端存在用户目录初始化错误，因此实际设备证据使用 scripts.zip 中的 adb_client.py，连接已运行的本机 ADB 服务器 127.0.0.1:5037。它实现 shell v2 退出码及 sync，不启动服务器、不复制密钥；不存在 ADB 服务器时应先在正常终端用阶段 sdk/platform-tools/adb.exe 启动。PowerShell 脚本的语法校验与 Python 实际运行证据分别记录，不把语法通过当作设备执行通过。

```powershell
python -B "$stage/run_device.py" --serial REPLACE_WITH_DEVICE_SERIAL --apk $apk --label manual-jni-20261106a --install --probe CompatProbe --timeout 180
python -B "$stage/run_device.py" --serial REPLACE_WITH_DEVICE_SERIAL --apk $apk --label manual-repair-20261106a --probe StabilityProbe --mode repair --timeout 480
python -B "$stage/run_ui.py" --serial REPLACE_WITH_DEVICE_SERIAL --apk $apk --label manual-ui-20261106a --font 1.0 --nav current
```

label 使用 ASCII 字母、数字和连字符。run_ui.py 将自动恢复它成功修改的字体、导航、模拟刘海覆盖层和模拟器硬件键盘下显示软键盘设置；真实设备不提供某项修改权限时该组记录 FAIL/BLOCKED，不强行 root 或改动安全设置。

## 模拟器矩阵与界面复现

本轮 API 26/29/35 使用 Google APIs x86_64 镜像；31/33/36 使用官方 AOSP x86_64 镜像。下载脚本读取对应官方元数据，完成校验后才解压；Google Play 服务不是当前隔离用例前提。API 34 由 realme Android 14 提供实际设备证据。所有模拟器实际进程均为 x86_64、4096 页，不作为 ARM64 或16KB证明。API 35 镜像声明的 ARM 转译能力也不计入 ARM 实测。

下面示范 API 35；其余 API 逐项使用未占用的显式端口。启动前确认本机 ADB 服务器可用；start_emulator.py 的冷启动预算为240秒。模拟器、日志、缓存和 AVD 都在新阶段目录，未配置虚拟化或启动失败应记录 BLOCKED，不降低 API 代替。

~~~powershell
python -B "$stage/download_sdk.py" --kind image --api 35
if ($LASTEXITCODE) { throw 'Image download/verification failed' }
python -B "$stage/start_emulator.py" --api 35 --port 5558 --flavor google_apis
if ($LASTEXITCODE) { throw 'Emulator start failed' }
$emulatorApk = "$output/ESurfingHunan-0.2.19-compat-s1-isolation-x86_64.apk"
python -B "$stage/run_matrix.py" --api 35 --serial emulator-5558 --revision manual1
if ($LASTEXITCODE) { throw 'Matrix contains failures; inspect evidence before continuing' }
python -B "$stage/keyboard_check.py" --serial emulator-5558 --apk $emulatorApk --label manual-api35-keyboard1 --nav gesture --cutout
if ($LASTEXITCODE) { throw 'Touch/IME check failed' }
python -B "$stage/stop_emulator.py" --serial emulator-5558
if ($LASTEXITCODE) { throw 'Emulator cleanup not confirmed' }
~~~

31/33/36 的下载额外指定 --flavor default，启动同样指定 default。下载需联网，可能耗时；测试过程中不得将隔离端点改为生产端点。run_matrix.py 每个子用例有独立超时，单个设备全组上限按子项预算相加，不包含下载时间；修复与生命周期较慢是为了保留客户端等待及完整会话，不以高频真实认证缩短观察。

触控补测只操作隔离包的四页标签、滚动区域和输入框；不会按下连接、注销、清数据等按钮。keyboard_check.py 在2.0字体下检查所有关键按钮可达，并在键盘实际显示时最多滚动6次寻找完整保存按钮。复现时先运行UI探针生成合成设置，禁止将该工具用于主包。

cleanup 使用已记录序列号及 ro.kernel.qemu=1 双重确认，向该模拟器发送正常关机请求，最多等待60秒。它不结束 ADB 服务器，也不操作真实手机。若自动测试异常退出，请先执行 Restore-Compatibility.ps1 停止隔离包，再按证据原值恢复字体、导航和模拟刘海；模拟器最后使用 stop_emulator.py 关机。没有卸载或清除主应用数据步骤。

SEALED 是封存标记；阶段支持脚本拒绝在封存目录继续生成记录。未来补齐16KB环境须建立新的阶段1修订目录并重新绑定该修订的源码、APK和运行证据。

## 主包安装与回退

本次保留 realme 上原主包及运行会话；不把隔离安装称为主包覆盖安装。主包与旧版使用相同测试证书且 versionCode 递增，满足普通覆盖安装的签名/版本前提，但当前主包覆盖和真实认证尚未执行。

安装主包会终止旧进程，应在用户愿意中断当前会话时另行执行显式 adb -s 序列号 install -r 主APK。安装后手动打开并连接，不应自动恢复认证。安装失败保留原应用，不自动卸载、清数据或降级。回退到旧 versionCode 受系统降级与数据兼容约束；不承诺无损直接回退，先保留旧 APK 和本次记录，遇到异常停止使用新版本并单独确定回退步骤。

## 证据白名单

只收集包名/版本/APK 哈希、设备型号/API/ABI/页大小、测试 ID、合成用例计数、资源计数、退出码、单调时刻和隔离页面截图。不要采集账号、密码、票据、密钥、凭据文件、完整 logcat 或完整抓包。不能把模拟、静态分析、脚本生成或历史结果记为当前真机 PASS。

API36 AOSP镜像实际将虚拟硬件键盘视为可用，默认可能只创建IME窗口而不显示输入视图。模拟器UI脚本临时将 show_ime_with_hard_keyboard 设为1，保存并恢复原值；不能只用 mInputShown 或 insets.isVisible(ime) 替代实际键盘截图和 mIsInputViewShown。真实手机不自动改此项。

API29 的旧 AVD 重启后曾缺少 Wi-Fi Network 对象，相关修复/生命周期用例记录 FAIL。重新创建同镜像独立 AVD 并显式使用空闲端口5566后，先执行 ensure_emulator_wifi.py 检查前置条件，再进行最终APK回归。旧 AVD 的启动/注册失败记录保留；ADB host:emulator 通知尝试没有恢复连接，不记为成功。残留进程在核对可执行路径属于本阶段后清理。此环境处置不改变真实手机网络。

API33 使用黑色三键导航栏和浅色图标；API34及以后保留浅色系统栏外观。当前大字体模拟器截图仍发现系统状态栏时钟裁切，UI视觉项保留FAIL，详见验收报告，不能用控件自动断言PASS代替整体验收。
