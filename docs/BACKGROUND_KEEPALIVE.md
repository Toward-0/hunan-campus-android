# Android 后台心跳修订 v36

当前候选为 **0.2.24-background / versionCode 36**。本次将已审核的源码、65文件固定交付和11个公开复现脚本同步到仓库，不重新构建APK，也不创建Release。固定交付中的“未推送”“仅本地”等说明属于构建完成时快照，保留原字节；以本页及仓库当前状态说明本次同步。

目标是使用 Android 标准机制覆盖 API26 起的设备，不依赖 realme 私有接口。v34 在 realme 的只读诊断中出现非精确唤醒闹钟延迟约187秒、另一次任务完成比计划晚约287秒；这是调度风险证据，不能单独归因全部断连。

每个心跳/定期外网检查同时安排进程内计时器和系统唤醒闹钟，竞争同一一次性任务。清醒时避免仅靠非精确闹钟的批处理；深度Doze中未获得电池豁免时，计时器保留已注册闹钟的执行窗口。闹钟注册失败仍允许计时器降级。保留代次检查、取消、有限重试和60秒请求唤醒锁，不新增自动账号提交、开机登录或永久唤醒锁。

“更多→后台运行”展示精确定时、电池优化、通知状态，并提供用户主动设置入口及系统入口回退。权限不构成登录硬门槛。会话中授予新权限后，后续计划采用新能力；若要立即应用，可停止后手动连接。任务卡锁定、取消“暂停闲置应用活动”不等同于电池豁免。

所有厂商都使用同一调度实现。手机系统仍可能限制后台或断开Wi-Fi；网络丢失、身份变化、进程结束后保持手动连接规则。界面的厂商提示仅是参考，不能宣称未实测品牌已经适配。

本轮 realme RMX3820/API34 已实际找到独立开关：系统应用详情 → 耗电管理 → **允许完全后台行为** → 允许。关闭时，系统的附加 `adjustment` 策略将两个已注册闹钟延后259200000毫秒（三天），尽管标准电池豁免和精确定时均已开启且前台服务仍存活。开启该开关后 `adjustment=--`、`whenElapsed=origWhen`，三天附加延期立即消失。只调整本应用此项，未开启应用自启动或关联启动。这个前后对照不等同于所有手机或8小时稳定性通过；心跳复测结果以validation为准。

该 realme 的实际入口为应用“更多”→“打开系统应用详情”→“耗电管理”→“允许完全后台行为”→允许。标准电池优化豁免、精确定时和最近任务锁定不能替代这个独立开关。其他厂商继续使用应用提供的标准系统入口，并按手机实际选项允许后台活动；本轮没有验证其他品牌的具体路径。

2026年11月8日23:06起的第二次观察保持同一已认证代次，没有重新登录。311.81秒 USB 连接下的普通锁屏中，新增心跳与外网结果均成功；心跳任务6的交付延迟为13ms，外网任务7为6ms，二者均在 `interactive=false`、`idle=false` 时执行。两次成功记录的时间戳间隔分别250167ms、300303ms，这是成功记录间隔，不是调度延迟。

设置调整前的311.77秒真实短测没有取得新增成功记录，保留FAIL。第二次原收集器只读取当前trace文件，遗漏已轮转到previous文件的心跳，因此原结果也保留FAIL。独立的轮转补齐记录只纳入原观察窗口、同一代次，八项检查通过；它没有改写原始失败。上述证据仅支持本机这一次短时普通锁屏，不能外推拔电深度Doze、8小时持续联网或耗电表现。

本轮20项记录为16 PASS、2 FAIL、2 NOT_RUN。两条FAIL保留设置前真实短测和设置后原收集器漏采；补齐后的短测PASS单独列项。完整Doze矩阵与8小时自然锁屏NOT_RUN。设计支持Android8.0/API26起，实际覆盖API26/API35 x86_64模拟器与API34 realme ARM64；当前ARM32进程、ARM64/16KB和其他品牌真机没有本轮运行证据。Lint主包0错误/16警告，隔离包0错误/36警告。

USB连接下的短时锁屏、强制Doze、拔电自然锁屏是不同测试。v35中间迭代的realme强制Doze在精确定时与电池豁免均开启时仍未收到预期回调，保留失败；这不转为v36通过。没有8小时自然锁屏或耗电证据，不宣称普遍长期稳定。公开脚本位于[tools/v36-background](../tools/v36-background/)，测试包与真实主包的操作边界继续保持。
