# 湖南校园网安卓项目完整工作流程

本流程用于继续开发、验证和交付湖南校园网Android APK，也说明日常连接、修复和换机的操作边界。当前版本及最新证据以[当前进度](CURRENT_STATUS.md)为准；截至2026年11月7日，阶段1整体未通过，后续阶段尚未获准开始。

从[顶层README](../README.md)开始阅读。`source/`为Android工程，`docs/`为本次交接文档，`artifacts/main/`和`artifacts/isolation/`分别保存主包和隔离包，`evidence/`保存原清单及经过筛选的摘要证据。`source/README`中的旧版本信息保留为历史内容，不作为当前交付入口。

## 一 用户使用流程

### 安装或升级

1. 核对主APK文件名、版本、包名、SHA256与签名证书摘要。主包为`org.esurfing.hunan`；名称含isolation的测试包为`org.esurfing.hunan.isolation`，不能混用。
2. 先核对手机实际supported ABIs、系统API和页大小。主包包含arm64-v8a及armeabi-v7a，但某台手机只支持64位时不能强行做32位测试。
3. 同签名覆盖安装应保留本地数据，不自动卸载或清除主应用。更新会结束旧进程，需要时用户重新打开并手动连接。
4. 正式签名迁移可能不能覆盖原测试签名安装，不承诺无损直接升级。当前测试私钥由用户本地保管，不上传GitHub或复制到交付包。

### 账号密码连接

1. 在系统中直接连接校园Wi-Fi，打开主应用，按实际需要处理系统权限提示。
2. 在账号页输入账号和密码。首次跨手机验证保持门户、IP、网关、MAC、mscgip、主机名等高级项为空，以验证自动发现；不要从另一手机复制身份参数或票据。
3. 仅主动点击一次“保存并连接”。活动连接、认证、注销、修复期间不得替换账号配置；先按提示停止或完成注销。
4. 区分“认证接口接受”“首次心跳成功”与“HTTPS外网检测通过”。只有keep成功不能认定外网可用；单个HTTPS失败也不能直接判定需要修复。
5. 错误或网络变化后按提示停止，保留本地数据和白名单诊断，不连续点击登录制造重试。

### 停止 注销 修复和换机

| 操作 | 含义 |
|---|---|
| 停止连接 | 停止本机工作；不请求服务器注销 |
| 注销并停止 | 用户确认后请求服务器结束当前会话；只有认可的响应才算注销成功 |
| 更多→修复网络 | 常驻入口，可查看条件；实际修复只适用于本机已认证且持续受到门户拦截的有效会话 |
| 关闭应用/断开Wi-Fi | 不能据此认定服务端会话已经注销 |

修复顺序必须是：门户证据满足原门槛→用户确认→自身注销成功响应→客户端等待100秒→至多一次重新登录→验证结果。等待可以取消；100秒是客户端策略，不是已证实的服务端要求。没有本机认证会话或票据时，不能用修复按钮强制重登或踢掉另一设备。

换机时先在原手机仍联网、仍保有会话时手动点击“注销并停止”，确认成功后断开，再在新手机手动连接。若原会话已丢失本地票据，不通过重复认证来尝试恢复注销能力，必要时另行制定受控测试或由用户使用官方渠道核实账号状态。

## 二 每轮开发开始前

1. 阅读当前进度、完整流程、原稳定化设计审查和相关验收报告。找到真正的最新源码与APK绑定，不能把最近修改日期或测试目录当作新版本。
2. 只读核对APK哈希、源码清单、版本与签名；联合读取历史目录，不假定每个目录都有同名文件。
3. 核对构建入口、工具链版本及全部写入路径：Gradle缓存、Android用户目录、临时目录、AVD、构建产物、签名输出、报告。旧工具链和测试签名只读复用。
4. 核对本机镜像、虚拟化能力、设备、ABI、页大小和可用磁盘空间。只依据实际接入设备，不猜测型号或能力。
5. 将问题分类为已证实缺陷、待验证假设、已知限制。先定义测试与通过标准，再改代码。
6. 每阶段开始前提交5—8行计划，含范围、数值门槛、所需设备/用户操作，等待用户确认。阶段结束可同时给下一阶段计划，用户确认该计划即授权进入，无需重复询问。

已确认范围内连续完成可自主执行的工作；缺少真机回传时继续不依赖它的部分。不得等待超时后自行当作用户批准或测试通过。

## 三 文件和测试隔离

每阶段及每次封存交付后的修订均使用新的`work/<阶段名-唯一标识>/`和`outputs/<阶段名-唯一标识>/`。旧目录含缓存、报告、日志、APK在内一律不回写。当前目录可迭代，封存后另起目录。

先复制源码并参数化路径，再运行构建。严禁在基线目录运行Gradle、格式化、清理或测试。开始和结束核对受保护基线哈希。Git工作副本、可写缓存、临时目录和输出都必须在新阶段；若仓库提供移植脚本，应按本阶段根目录显式设定，不隐式沿用旧路径。

离线集成、压力、故障注入只使用隔离包、`127.0.0.1`、合成动态模块、虚构账号和票据。优先设备/模拟器内部回环；如果使用主机服务器，必须明确adb reverse映射及退出后的清理，手机的127.0.0.1不是电脑的127.0.0.1。测试路径不得回退到生产认证或外网端点；测试入口、合成模块和故障注入不得进入主APK。

主应用数据不得用于破坏性测试。Keystore损坏、清数据、迁移故障、并机模型等使用隔离包。真实手机可以由代理按用户已有授权执行安装、隔离测试、权限/系统测试及白名单采集，但需要显式设备、包名、APK及测试边界；**真实账号认证、注销、确认修复由用户手动发起**。

## 四 不得改变的安全行为

- 选定网络丢失或身份变化后安全停止，等待手动连接；不在另一网络偷偷重放账号。
- 进程终止、用户force-stop、重启后不自动认证；下次打开显示适当中断状态。不开机自动登录。
- 修复必须由用户确认；仅在自身注销获协议认可后允许原等待策略及至多一次重登。
- 停止、网络变化、服务结束、证据过期取消待执行修复。
- 保留代次隔离、取消保护、网络绑定、传输资源释放、必要的同步持久化语义。
- 不修改生产认证协议、端点、MAC或客户端标识策略。不为了兼容性跳过身份校验、信任所有TLS证书或复用另一手机身份。
- 不增加无界重试、永久WakeLock或后台自动账号POST。简约四页界面继续保留。

## 五 阶段1 兼容性基建

### 当前优先修订

下一步仍停留阶段1。先提出新修订计划，建议优先处理成功后的旧`protocolCode`残留、诊断JSON首行截断，以及API35大字体系统栏和UI探针页码证据问题。它们分别需要独立预期结果，不可把诊断修正包装成解决服务器真实105。

新源码交付versionCode必须大于33，并采用可追溯versionName。只迁移、归档或在另一设备测试完全相同APK不产生新版本，也不能声称重新构建。修改源代码后须完成本次受影响用例和新的绑定。

### ABI与JNI

保留arm64-v8a、增加/维持armeabi-v7a，审查JNI句柄、指针/整数转换、size_t、长度计算、LzmaDec、分配失败和边界。不要预设某处一定存在缺陷。

分别在实际32位和64位进程运行正常解压、畸形/截断输入、加解密往返、重复创建释放，记录加载ABI、进程位数、句柄释放。先核对supported ABIs；arm64安装成功或x86_64测试通过不能代替v7a运行。缺少32位环境时写“未通过（缺少32位运行证据）”。

### UI与16KB

UI覆盖四页、系统栏、刘海、手势/三键导航、键盘、大字体下关键控件可见可操作，截图绑定设备/API；补旧系统布局回归。UI探针必须核对实际前台和页码，不能只依赖自动PASS。

16KB单独交付四类证据：适用64位原生库ELF LOAD段对齐；最终APK `zipalign -c -P 16 -v 4`；原生页大小假设审查；ARM64且PAGE_SIZE=16384环境安装/启动/JNI。任何一类不能代替其余类别，x86_64运行不能冒充ARM64。

隔离矩阵至少API26/29/31/33/35；实施前确定API34和36的必选或补充定位。模拟器需要x86_64时，仅为隔离构建增加。镜像、虚拟化、ABI或空间不足如实BLOCKED。

阶段门槛是双ARM构建、签名、适用对齐、UI、约定矩阵及32/64位JNI必选项全部有PASS证据。用户接受“保留16KB阻塞”没有取消这一门槛，也没有默认授权推进阶段2。

## 六 阶段2 后台调度与心跳时效

执行顺序固定为：现状测量→调度与权限改进→隔离回归→短时Doze矩阵→真机8小时锁屏。实施前提交并让用户确认时效、断线和耗电阈值。

首次连接前集中展示精确闹钟能力、电池优化豁免和通知权限，按API检查，每个请求由用户主动触发。通知首次使用系统运行时权限流程，必要时提供设置入口；未授权仍可连接，以非打断方式提示能力缺口。从设置返回重新检查；覆盖拒绝、撤销、设置页不可用和OEM差异。新增REQUEST_IGNORE_BATTERY_OPTIMIZATIONS前解释用途并有系统设置回退。权限不得擅自变成登录硬门槛。

区分首次心跳、后续心跳与外网探测，检查唤醒配额和同一工作队列竞争，记录真实调度模式及降级原因；精确闹钟不等同准时保证。用单调时钟记录计划、闹钟交付、任务进入、请求开始/完成，分别计算调度延迟、队列等待、请求耗时；墙上时间仅人工关联。保留有限退避和代次取消。

Doze矩阵只覆盖系统实际可实现的精确闹钟/豁免组合，记录canScheduleExactAlarms、真实豁免、调度模式、通知状态、API和确实进入Doze的证据。不要将设置开关假定为相互独立。每组预先约定时长、最少样本数和数值阈值，输出样本数、P50/P95/最大延迟、成功心跳间隔、缺失任务及失败原因；样本不足不造稳定结论。

静默门户拦截优先复用现有InternetCheck及SessionRepairGate：keep成功不等于外网可用；单个HTTPS失败不触发修复；区分门户证据、DNS/TLS/站点故障和未知状态；门槛满足仅提示，确认后才进入注销/等待/一次重登，取消路径全部验证。不得增加重复调度或额外自动认证。

8小时先在realme开展，区分强制Doze与自然锁屏。自然锁屏拔掉实际充电连接，避免频繁ADB轮询或唤醒；模拟“未充电”不能代替真实耗电条件。记录有效时长、心跳/探测样本、最大延迟/间隔、断线、进程/网络/代次变化、用户确认修复次数、电量和可获取指标。耗电对照列设备、亮度、网络、起始电量、后台负载、观察时长差异，不给虚假精度。TTL未知就写未知，采样间隔不能称连续外网通过。

进程终止分别验证普通终止、内存压力、force-stop、任务划除、重启；kill -9不等于真实LMK。检查中断提示、残留任务、资源与手动重连，不自动重登或开机启动。

## 七 阶段3 厂商与生命周期

复用已有模拟器结论，只补受影响用例。对MIUI/HyperOS、ColorOS/realme UI、OriginOS、MagicOS、One UI整理保活设置说明，记录来源、系统版本、核实日期；未实机验证路径标为参考，不能称厂商适配通过。厂商后台自启动设置与应用开机自动登录是不同概念。

隔离回归覆盖并机互踢模型、全新首启、权限拒绝/撤销、Keystore失效、旧版覆盖升级和结构迁移。Keystore失效应安全提示重输，不明文降级，不把不可恢复凭据伪装为迁移成功。所有破坏性用例仅作用于隔离包及合成凭据。

真实并机测试先给低频受控方案，由用户执行；按实际提供设备逐台验收归档。当前已明确的realme和iQOO不意味着其他型号已经可用，小米历史信息未知型号时不猜。

## 八 阶段4 收尾交付

正式签名只提供密钥自持、备份、访问控制、恢复、证书记录和换签安装/数据影响方案，不生成或接管用户正式密钥，不承诺换签必然覆盖安装。

Lint重新核实数量，目标零错误、无未处置有效警告。逐项区分真实问题、误报和支持范围外提示。不得机械commit改apply、破坏凭据/停止状态同步持久化、全局关闭检查、降级或滥用baseline。局部抑制记录规则ID、位置、理由和验证；原始警告非零仍如实报告。

真实故障统计先定义故障分类、样本数、成功条件、观察窗，再由用户执行。模拟与实网分开；分别报告检测率、误报率、确认后修复成功率、耗时及取消安全性。零样本不写100%，仅有方案时只写方案完成。

最终报告分别列设计支持、已验证系统/ABI/页大小/设备、未验证与已知限制，并给安装升级、回退条件、签名和证据索引。最终源码与APK重绑定，改动影响哪些用例就补哪些；旧构建结果只能按其真实构建标识引用。

## 九 实网验证和手机脚本规范

每份实网方案先写登录/注销上限、只读探测频率、最长观察时间、停止条件和失败处理。真实账号动作由用户执行；保持正常心跳和原有有预算探测，禁止高频认证、注销或故意制造风暴。一般初次连通确认可采用登录最多1次、注销0次、修复0次、最多5分钟，但这不是所有后续测试的自动预算，具体方案需明确。

Windows PowerShell/adb脚本必须用显式`$Serial`、`$PackageName`和`$Apk`，验证在线状态、包名、版本/哈希、supported ABIs与退出码，有超时、停止条件、清理/恢复。不得默认root、自动卸载/清空主包，或默认当前连接的是上一台设备。

回传只采用字段白名单：状态、枚举、数值错误码、代次、调度时间及预先允许环境字段。不得导出账号、密码、票据、密钥、凭据文件或完整抓包，也不得先全量采集再事后脱敏。高级配置需要核查时可只输出是否设置，不输出值。

## 十 归档 验收和GitHub协作

每阶段交付：逐文件增删改及前后SHA256的changes.json；source-manifest.json与文本差异；APK/源码包/脚本和SHA256SUMS.txt；工具链版本、完整构建命令、退出码、签名、Lint；复现/手机/清理恢复说明；validation.json与中文报告。

每条验收绑定测试ID、源码/构建标识、APK哈希、环境、预期、实际、证据和时间，状态只用PASS、FAIL、NOT_RUN、BLOCKED。必选项非PASS则阶段结论未通过，默认留在当前阶段。脚本已生成、静态检查、模拟结果、历史通过都不能冒充当前真机通过。

GitHub上传采用经过审查的文件白名单，保存源码、必要依赖及许可证、可公开的构建说明、版本清单、受限数据的摘要证据、APK和交接文档。排除工具链/Gradle/AVD缓存、签名私钥、账号凭据、完整设备诊断、私有配置及无必要个人/设备标识。原封存资料不就地修改；对外文档是新衍生文件，列清原始证据来源和遗漏范围。

本次源目录发布副本保持运行源码与构建文件不变，仅对`source/docs/阶段1复现与真机操作.md`里的真实序列号作占位替换，记录于`publication-changes.json`及新的发布`source-manifest.json`。原APK的构建输入仍以`evidence/original-source-manifest.json`及原始哈希绑定；不要用经过脱敏的发布清单倒签原APK。后续重新构建必须绑定实际输入和新测试记录。

每次后续优化开新分支或独立修订，提交围绕实际问题与行为说明，附受影响测试和未解决项。不得无审核发布测试入口到主包，或因仓库已建立就自动开始下一阶段。仓库可见性、发布范围和授权以用户实际选择为准。
